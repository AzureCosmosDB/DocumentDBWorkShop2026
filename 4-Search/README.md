title: Search in Azure DocumentDB
description: Run keyless Python, Node.js, and C# search samples with Azure DocumentDB and Azure OpenAI
---

**Duration:** 75 minutes

Build a search workflow that generates embeddings, stores them with documents,
creates search indexes, and compares semantic, keyword, and hybrid retrieval.

## Learning goals

* Authenticate to Azure DocumentDB and Azure OpenAI with Microsoft Entra ID
* Generate embeddings with `text-embedding-3-small`
* Create a DiskANN vector index
* Run vector retrieval with `cosmosSearch`
* Run BM25, fuzzy, and phrase retrieval when full-text search is available
* Combine vector and keyword rankings with Reciprocal Rank Fusion (RRF)

## Prerequisites

* Complete the Module 1 environment-access lab
* Complete the Module 2 indexing lab
* Use the selected Python, Node.js, or .NET environment provided on the
  workshop VM
* Restart the terminal or notebook kernel after environment setup

## Lab step 1: Configure the environment

From the workspace root, sign in and run the shared setup script:

```powershell
az login
./1-DocumentDB-Introduction-and-Cluster-Setup/Set-LabEnvironment.ps1
```

Expect the script to display `DOCUMENTDB_CLUSTER_NAME`,
`AZURE_OPENAI_ENDPOINT`, and `AZURE_OPENAI_EMBEDDING_DEPLOYMENT`.

## Lab step 2: Choose a language track

### Python

Open [the Python search notebook](before/python/4_Search_DocumentDB.ipynb),
select a Python kernel, and run the cells in order. Complete each `STUDENT
EXERCISE` before comparing your work with the
[completed Python reference](after/python/4_Search_DocumentDB.ipynb).

### Node.js

```powershell
Set-Location ./4-Search/before/nodejs
npm start
```

### C#

```powershell
dotnet run --project ./4-Search/before/csharp/DocumentDbSearch.csproj
```

All tracks use `AzureCliCredential`. Do not add a connection string, database
password, or Azure OpenAI API key.

## Lab step 3: Load and index the documents

Observe the sample as it embeds each document and stores the vectors in the
`docdbworkshop.workshop_content` collection. Confirm that the reported vector
dimension matches the embedding response.

Create or verify the DiskANN index named `idx_embedding_diskann`. The cluster
must use a tier that supports DiskANN.

The lab also attempts to create `idx_body_fts`. Full-text search is a gated
preview. A server response with code `115` means the feature is not enabled on
the assigned cluster; it is not an authentication failure.

## Lab step 4: Run the search patterns

Run vector search and inspect each projected `searchScore`. When full-text
search is enabled, also run:

* BM25 keyword search
* Fuzzy search with a misspelled query
* Phrase search with ordered terms

Record which documents rank first for each retrieval method and note where the
rankings differ.

## Lab step 5: Compare hybrid retrieval

Review how RRF combines vector and keyword positions without comparing their
raw scores directly. Identify one result promoted because it appears in both
ranked lists.

Module 4 keeps up to five results for retrieval-method comparison. Module 5
reduces the context to three results to keep its grounded prompt concise.

If full-text search is unavailable, complete the vector path and discuss how
the keyword list would contribute to RRF when the preview is enabled.
